# TikTok配信用ビンゴ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** リスナーがURLから枚数を申請し、主催者が許可した分だけカードが配られ、主催者の番号発表に全員のカードが連動するビンゴを `bingo/` に作る。

**Architecture:** Cloudflare Workers 1つ。静的ファイル(Workers Static Assets)が2つの画面を配り、Durable Object `BingoRoom`(1個、SQLite保存、WebSocket Hibernation)が状態と通信を持つ。抽選・カード生成・判定はサーバー側。純粋関数は `public/logic.mjs` に置き、サーバー・ブラウザ・テストで共用する。

**Tech Stack:** Node.js 22、wrangler ^4.161.0(開発用のみ)、素のHTML/CSS/ES Modules、`node --test`、Playwright(環境にプリインストール済み。`createRequire` で読み込む)。

**Spec:** `docs/superpowers/specs/2026-11-13-bingo-design.md`

## Global Constraints

- すべて `bingo/` の中。既存の株式分析・スゴロクのコードには触れない。
- フレームワーク・ビルド工程・外部スクリプトなし。インラインの `<script>` も置かない(CSPが `script-src 'self'`)。
- カード: 5×5、1〜75、中央FREE(値は `0`)。列の範囲は B 1–15 / I 16–30 / N 31–45 / G 46–60 / O 61–75。
- 上限: 名前20文字、1回の申請50枚、部屋全体5,000枚、申請中1,000件。
- 反映の遅れ: `0, 3, 5, 8, 10, 15, 20, 30` 秒のいずれか。初期値 `0`。
- 受付の初期状態は締め切り。
- 画面は日本語のみ。音は出さない。スマホ縦持ち(幅390px)優先で、PCでも崩れない。
- リスナーが入力した名前は `textContent` でのみ表示する。`innerHTML` にユーザー由来の文字列を入れない。
- 主催者の合言葉はシークレット `HOST_PASSWORD`。未設定なら誰も主催者になれない。リポジトリに入れない。
- 必要な状態はすべてSQLiteに置く。メモリ上の情報は消えてよいものだけ。
- 確認ダイアログは `window.confirm` を使わず、ページ内の `<dialog>` で出す(アプリ内ブラウザで抑止されることがあるため)。
- テストを先に書く。各タスクの最後にコミットする。

## Review Focus

仕様が暗に求めるが、放っておくとテストされない入力・状況。各行のテストは担当タスクに入れてある。

1. アプリを切り替えて戻る・圏外から復帰する → その間に発表された番号が、操作なしで反映される(Task 6 の e2e)。
2. Durable Object が休止・再起動する → カード・番号・申請が残り、つなぎ直した人に同じカードが届く(Task 5)。
3. 主催者の二度押しや行き違い(同じ申請を2回許可、取り消し済みを許可、番号がないのに取り消し、75個出たあとに引く) → 二重に配らず、エラーを返して動き続ける(Task 3・4)。
4. 壊れた入力(JSONでない、`count` が `"3"`・`2.5`・`-1`・`1e9`、名前が空白だけ・21文字、番号が `0`・`76`・`"x"`) → エラーを返し、他の人への配信は止まらない(Task 3・4・5)。
5. 同じリスナーが2つのタブを開く → 両方に同じカードと番号が届き、申請は1件のまま(Task 3)。

## 通信の取り決め

すべて `{ "t": 種類, ... }` のJSON文字列。この節は全タスクが参照する。

**ブラウザ → サーバー**

| t | 送る側 | 中身 |
|---|---|---|
| `hello` | リスナー | `token`(小文字16進64桁) |
| `request` | リスナー | `name`, `count` |
| `cancel` | リスナー | なし |
| `auth` | 主催者 | `password` |
| `accepting` | 主催者 | `on`(真偽) |
| `delay` | 主催者 | `sec` |
| `approve` | 主催者 | `id`, `count` |
| `approve_all` | 主催者 | なし |
| `reject` | 主催者 | `id` |
| `draw` | 主催者 | なし(ランダム) |
| `call` | 主催者 | `n` |
| `undo` | 主催者 | なし |
| `block` / `unblock` | 主催者 | `pid` |
| `new_round` / `reset_all` | 主催者 | なし |

**サーバー → リスナー**

- `state`: `{ accepting, delay, draws: number[], lastAge: number|null, winners: W[], you: Y }`。`hello` への返事。
- `you`: `{ you: Y }`。その人の申請・カードが変わったとき。
- `draw`: `{ n, seq, winners: W[] }`。`winners` はこの番号で新しくビンゴした分だけ。
- `undo`: `{ seq }`。`seq` 番目の番号と、`at === seq` のビンゴを消す。
- `winners`: `{ winners: W[] }`。全件の置き換え(途中配布やブロックで変わったとき)。
- `accepting`: `{ on }`、`delay`: `{ sec }`、`round`: `{}`(番号とビンゴを消す)、`reset`: `{}`(すべて消し、未申請に戻す)。
- `error`: `{ code }`。

`Y = { name: string|null, blocked: boolean, pending: number|null, rejected: boolean, cards: { no: number, numbers: number[] }[] }`
`W = { rank: number, name: string, no: number, at: number }`(`at` は何個目の番号で達成したか)

**サーバー → 主催者**

- `host`: `{ accepting, delay, draws, winners: W[], requests: R[], players: P[], blocked: { pid, name }[] }`。
  認証の直後と、`draw` `call` `undo` `block` `unblock` `new_round` `reset_all` `approve_all` `accepting` `delay` のあと。
- `req_add`: `{ req: R }`、`req_del`: `{ id }`、`player`: `{ player: P }`(追加または更新)。
- `auth_fail`: `{ reason: 'wrong' | 'locked' | 'unset' }`、`error`: `{ code }`。

`R = { id, pid, name, count }`、`P = { pid, name, cards, bingo, reach }`(`bingo` はビンゴしたカードの枚数、`reach` はビンゴしておらずリーチのカードの枚数。カードを1枚以上持つ人だけ)

**エラーコード:** `bad_message` `need_hello` `forbidden` `bad_name` `bad_count` `closed` `already_pending` `blocked` `busy` `no_pending` `not_found` `cards_full` `bad_number` `already_called` `all_called` `nothing_to_undo` `bad_delay`

合言葉の比較は、両方の SHA-256 を `crypto.subtle.timingSafeEqual` で比べる。`HOST_PASSWORD` が空なら `auth_fail unset`。
失敗の記録は接続元(`CF-Connecting-IP`、なければ `'unknown'`)ごとに `auth_fail` 表へ。5回連続で失敗したら5分間 `locked`。成功で消す。
JSONでない・オブジェクトでない・`t` が文字列でないメッセージは `error bad_message`。2,048文字を超えるメッセージは接続を閉じる(コード1009)。
1接続あたり10秒に30通を超えたら閉じる(コード1008)。回数はメモリ上でよい。

- [ ] **Step 1: 失敗するテストを書く**

次の振る舞いを1つずつテストにする(各テストは `fresh` から始める)。

| テスト名 | 確かめること |
|---|---|
| 受付が締め切りなら申請は closed | 初期状態で `request` → `error closed` |
| accepting は全員に届く | 主催者が `accepting on` → リスナーに `{ t:'accepting', on:true }`、主催者に `host`(`accepting: true`) |
| 申請すると主催者に req_add、本人に you | `you.pending === 3`, `you.name === 'たろう'`, `you.cards` は空。`req_add.req` は `{ id, pid, name:'たろう', count:3 }` |
| 許可するまでカードは届かない | 申請後、`you`(cards あり)が来ない(`none`) |
| 許可すると許可した枚数が本人にだけ届く | `approve { id, count: 2 }` → 本人の `you.cards.length === 2`、`no` は 1, 2、各 `numbers` は25個。別のリスナーには `you` が来ない。主催者に `req_del` と `player`(`cards: 2, bingo: 0, reach: 0`) |
| 追加申請でカード番号が続く | もう一度申請・許可 → `no` が 3 から |
| 却下 | `reject` → 本人の `you.rejected === true, pending === null`。再申請できる |
| 取り消し | `cancel` → 主催者に `req_del`、本人の `you.pending === null, rejected === false`。申請がないのに `cancel` → `no_pending` |
| 1人1件 | 申請中にもう一度 `request` → `already_pending` |
| 名前と枚数の検証 | `name: '   '` と21文字 → `bad_name`。`count` が `0, 51, 2.5, -1, 1e9, '3'` → `bad_count` |
| カードを持ったら名前は変わらない | 別の名前で追加申請しても `you.name` と `req_add.req.name` は最初の名前 |
| 二度押しで二重に配らない | 同じ `id` を2回 `approve` → 2回目は `not_found`、カードは増えない |
| 取り消し済みは許可できない | `cancel` のあと `approve` → `not_found` |
