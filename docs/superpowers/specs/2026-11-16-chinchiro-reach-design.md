# チンチロ対決 第2弾 設計書: 音の確実化・リーチ演出・ルール表・履歴・持ち点

2026-11-16。対象: `chinchiro/`(配信者 vs リスナーのチンチロ対決)。前作の設計は `2026-11-15-chinchiro-design.md`。

## 目的と背景

配信で何戦か遊んだ利用者(配信者。技術者ではない)からの要望:

1. サイコロの音が鳴らない時がある(端末・状況は「両方 / よくわからない」)。
2. 演出をもっと派手に。
3. 強い役になりそうな時は、最後の1個が着地する瞬間にズームするなど、パチンコの「リーチ」のような要素を入れたい。リーチの強さは結果のヒントにしてよい(パチンコと同じ「信頼度」。ガセもあり)。
4. ルールを知らない人のためのルール表。
5. 出た目のお互いの履歴を表示。
6. 持ち点を設定できるように(部屋を作るとき)。

配信の「見せ場」を作ることが全体の狙い。リスナーは待ち時間が長いと離れるので、演出は長くても1投あたり +3.5 秒まで、タップで飛ばせることは維持する。

## ゴール・やらないこと・失敗の定義

ゴール

- 音: iPhone の消音スイッチ、ブラウザの自動再生制限、電話などの割り込み後、のどれでも「何かをタップすれば必ず鳴る」状態にする。鳴らせない間はそれが画面で分かる。
- リーチ: 2個目までの目で「役になりそう」なとき、最後の1個を空中で溜めてズーム・暗転・鼓動音・カットイン。強さは3段階(ノーマル / スーパー / 激アツ)+ 悪い役の「ピンチ」。強い役が出るときほど強い演出が出やすいが、確定ではない。全端末で同じ映像(seed から決める)。
- 通常の投げと結果の演出も一段派手に(砂煙・揺れ・光の筋・集中線・画面全体のフラッシュ)。
- ルール表: 親機・スマホのどちらからも1タップで開ける。役の絵(サイコロ)つき。今の部屋の設定で実際に何点・何口動くかも書く。配信画面には常に小さな役の順位を出す。
- 履歴: 対戦中は親と子の 1〜3 投目を並べて見せる。過去の対戦は直近 30 戦を記録し、親機とスマホの両方で見られる。
- 持ち点: 部屋を作るときに 50 / 100 / 300 / 1000 か自由入力。全員その点から。

やらないこと

- 途中での持ち点変更(要望で「部屋を作るとき」と決定)。
- Firebase のセキュリティルールの変更(利用者がまだ前回分を貼り直していない。今回はルール変更なしで作る)。
- 音源ファイルの追加(効果音はこれまで通りその場で合成。役名コールの音声ファイル対応は前回済み)。
- 表示専用(配信ソース用 `stage=1`)の音を出すこと(二重に鳴るので従来通り無音)。

失敗の定義

- 止まる前に結果が分かってしまう(前回の指摘。リーチの強さは「ヒント」までで、確定情報は出さない)。
- リーチで毎投 3 秒以上待たされる(激アツは 5% 程度の頻度に抑える)。
- 端末間で映像が食い違う。
- 既存のテスト(ロジック・同期・画面 e2e・スゴロク)が落ちる。

## 制約

- 素の HTML/CSS/JS、ビルドなし、GitHub Pages。Firebase の JS SDK は gstatic から動的 import。
- 出目と演出の乱数は親機が決めた `throw.seed` から全端末で同じに再現する(`mulberry32`)。
- Realtime Database のルールは変えない: 新しい保存先は、親機だけが書ける既存の `state` の中に入れる。
- iOS Safari: Web Audio は消音スイッチで止まるが `<audio>` 要素は止まらない。`<audio>` の `play()` はユーザー操作中に一度「解錠」した要素を使い回す必要がある(前回、役名コール用に 1 つ解錠済み)。
- テスト環境(Linux の Chromium): 音は出ないので、`AudioContext` と `Audio` を差し替えて振る舞いを確かめる。

## 作り方の候補と決定(作り手の判断)

利用者は結果(見え方)で話しているので、作り方は私が決めた。

| 項目 | 候補 | 決定と理由 |
|---|---|---|
| リーチの決め方 | A. 各端末が出目と seed から同じ計算で決める / B. 親機が決めて throw に書く | **A**。データを増やさず、全端末で同じ映像になる。既存の演出も同じ方式 |
| 履歴の保存先 | A. `state.log`(親機だけが書く既存ノードの中)/ B. `rooms/$code/log` を新設 / C. 端末内だけ | **A**。ルール変更なし、1 回の書き込みで結果と一緒に保存される。B はルールの貼り直しが必要。C は共有・再読み込みに弱い |
| 音の対策 | A. 無音ループで `<audio>` を鳴らし続ける + 操作のたびに再開 + 「タップで音をオン」表示 / B. 効果音を全部音声ファイルにする / C. 表示だけ | **A**。B は十数個の音を作り直す上に細かい合成ができなくなる。C は根本対策にならない |
| ルール表の中身 | A. 文言を固定で書く / B. ロジックの定数(倍率・単位)から作る | **B**。ルールと表が食い違わない |

## 1. 音が鳴らない問題

原因の候補と対策(「どの端末か分からない」ので全部つぶす):

| 原因 | 症状 | 対策 |
|---|---|---|
| iPhone の消音スイッチ | 効果音(Web Audio)だけ無音。役名コールの音声ファイルは鳴る | 最初のタップで無音の `<audio>` をループ再生し続ける(`loop`, `playsinline`)。これで iOS はページを「動画と同じ」扱いにし、消音スイッチでも Web Audio が鳴る(ゲームでよく使われる方法)。バックグラウンドで止まったら、画面に戻った時と次のタップで再開。**回すのは親機だけ常時、スマホは自分の対戦中だけ**(ループ中は iOS がそのページを「再生中」と扱い、聴いていた音楽が止まりロック画面に出るので、見ているだけのリスナーには回さない。対戦が終わったら止める) |
| 自動再生の制限 | ページを開いて一度も触らないうちにリスナーが振ると親機が無音 | `pointerdown` / `keydown` / `touchend` のたびに `AudioContext.resume()`(作成も操作の中で)。鳴らす直前に `state !== 'running'` なら `resume()` を呼び、300ms 以内に running になればその音を鳴らす(落とさない) |
| 電話・他アプリの割り込み後 | 復帰後ずっと無音(`interrupted` / `suspended` のまま) | `statechange` を見て、`visibilitychange` と次の操作で再開。無音ループも `play()` し直す |
| 鳴らせないことに気づけない | 「バグ」に見える | ミュートでないのに AudioContext が running でない間、親機とスマホの画面に `🔇 タップで音をオン` のバッジを出す(どこをタップしても消える)。表示専用は出さない |
| 読み上げ(役名コール)の初回 | iOS で最初の読み上げだけ出ない | 最初のタップで空の発話を 1 回流して解錠 |

実装の置き場: `anim.js` の `createSounds()`。`unlock()` を拡張し、`ready`(running か)と `onReadyChange(cb)` を追加。`app.js` は `document` の `pointerdown` / `keydown` / `visibilitychange` で `unlock()` を呼び、バッジの表示を切り替える。無音 WAV は 0.5 秒(data URI)。

## 2. リーチ演出(パチンコ風)

### 用語

- **最後の1個**: 3 個のうち最後に止まるサイコロ。どれを最後にするかは、出目から「いちばんドキドキする順」に決める。
- **リーチ**: 先に止まった 2 個で役の形が見えている状態。
- **レベル**: 0 = なし、1 = ノーマルリーチ、2 = スーパーリーチ、3 = 激アツ。悪い役の形のときは **ピンチ**(レベル 1〜2)。

### 最後の1個の決め方(`reachPlan(dice, shonben, seed)`)

出目 `[a,b,c]`(ションベンのときはリーチなし)。**止まる順そのものが結果を確定させないように**、形が見える順と見えない順を seed で混ぜる(チェック担当の指摘: 「2 つ同じなら必ず違う 1 つが最後」だと、4・5 が見えた時点で「目」が消えるなど、順番から結果の一部が確定してしまう):

| 出目の形 | 最後に止める目 | 見える形 |
|---|---|---|
| 3 つ同じ(ゾロ目・ピンゾロ) | どれでも(seed で選ぶ) | ゾロ目リーチ(1 なら「ピンゾロリーチ」) |
| 2 つ同じ + 1 つ違う(目) | 半々: 違う 1 つを最後(ゾロ目リーチ → 外れて「○の目」)/ 違う 1 つを先(ペアの片方と並ぶ。4・5・6 や 1・2・3 の 2 つになればその形、ならなければリーチなし) | |
| 4・5・6 | どれでも | シゴロリーチ |
| 1・2・3 | どれでも | ピンチ(ヒフミ) |
| バラバラ | 半々: 多数派(4・5・6 側か 1・2・3 側の 2 つ)を先(シゴロリーチ → 外れ / ピンチ → 助かる)/ 混ざった 2 つを先(リーチなし) | |

「見える形」は先に止まった 2 個だけから決める: 同じ目 → ゾロ目(1 なら ピンゾロ)、どちらも 4〜6 で違う → シゴロ、どちらも 1〜3 で違う → ピンチ、それ以外 → なし。これで「ペアが見えた → 役あり」のような**ゲーム自体の事実**以外は漏れない。

### レベルの決め方(信頼度)

seed から別系統の乱数(`mulberry32(seed ^ 0x9e3779b9)`。サイコロの軌道の乱数には影響させず、既存のテストと映像を変えない)で、**実際の結果**に応じた重みで引く。目安(作り手が微調整してよい):

| 結果 | L0 なし | L1 ノーマル | L2 スーパー | L3 激アツ |
|---|---|---|---|---|
| ピンゾロ | 0 | 5% | 25% | 70% |
| ゾロ目 | 0 | 20% | 45% | 35% |
| シゴロ | 0 | 25% | 45% | 30% |
| 目(ゾロ目リーチが外れる) | 70% | 22% | 6% | 2% |
| 目なし(シゴロリーチが外れる) | 75% | 18% | 5% | 2% |
| ヒフミ | 10% | 30%(ピンチ) | 60%(大ピンチ) | — |
| 目なし(ピンチが助かる) | 80% | 15%(ピンチ) | 5%(大ピンチ) | — |

見える形が「なし」ならレベル 0。「ピンチ」のときは最大レベル 2(激アツは出ない)。目の結果で見える形がシゴロ(例: 5・4 が先で 4 が最後)なら `目` の行の重み。

これで「激アツ」が出る頻度はだいたい 5% 前後、激アツのときに強い役(ピンゾロ・ゾロ目・シゴロ)になる確率はおよそ 6 割。ノーマルリーチはよく外れる。パチンコと同じ感覚。

デモ・テスト用に `?demo=1&dice=1,1,1&reach=3` でレベルを固定できる(デモ以外では無視)。

### 流れ(時間は目安。タップでいつでも飛ばせる = 即・結果)

1. 構え(手の中でカラカラ 0.55 秒)→ 風切り音で 3 個が器へ(既存)。先に止まる 2 個は従来どおり跳ねて止まる(砂煙を 5→8 個、器の揺れを少し強く、投げ込み時に器の上を光の筋が走る)。
2. **レベル 0**: 最後の 1 個は軽いスロー(速度 0.5、ズーム 1.08)で止まる。今の「毎回スロー+ズーム」より短く軽くして、リーチとの差をつける。
3. **レベル 1 以上**: 最後の 1 個は軌道の 58% 地点(高さ 50px、投げ込みから約 1.05 秒)で空中に止め、ゆっくり回し続ける(CSS の回転を足す)。このとき 2 個目はまだ跳ねている(着地は約 1.4 秒)。2 個目が止まった瞬間から溜めを数え、同時に:
   - 画面が暗くなり(ビネット)、最後の 1 個にスポットライト、テーブルを 1.3 倍ズーム(1 個の位置へ寄る)。
   - カットイン文字: L1「リーチ!」白、L2「スーパーリーチ!!」虹色+左右のランプ点滅、L3「激アツ!!!」赤金+赤黒の警告ストライプ+稲妻+画面の揺れ。ピンチは「ピンチ…」赤黒、大ピンチは「大ピンチ!!」。ゾロ目リーチで 1 が 2 つなら文字に「ピンゾロ」を添える。
   - 音: 鼓動(ドクン…ドクン…)。L1 は 2 回、L2 は速く 4 回、L3 は加速する鼓動+上昇音(キュイーン)。ピンチは低い唸り。
   - 溜め: L1 0.9 秒、L2 1.8 秒、L3 2.8 秒(最後の 0.4 秒は音を止めて真っ暗にする「無音の溜め」)。
4. 解放: 最後の 1 個が落ちる(速度 0.6 でズームのまま)。着地の瞬間に **ヒットストップ**(全アニメを 120ms 停止)+ 強い揺れ + 白フラッシュ + 大きな「カッ」。
5. 結果(既存の `showResult` を強化): 
   - ピンゾロ: 画面全体(オーバーレイ)が金色に 2 回フラッシュ、回転する光線(放射)背景、星と金貨の粒子 60 個、集中線、スタンプが 2 段階で弾む、金のチャイム 2 回 + ドン。
   - ゾロ目: 虹の光線背景、粒子 36 個、集中線。シゴロ: 青の光線、粒子 24 個。
   - リーチが外れて「○の目」「目なし」: ずっこけ音(下がるトロンボーン風)と灰色のスタンプ、暗転をゆっくり戻す。
   - ヒフミ: 既存の暗転+雷。ションベン: 既存(リーチなし)。
6. 役名コール(既存)。

スキップ: 既存の `skip()` を拡張し、リーチの溜め・鼓動・カットイン・ヒットストップもすべて止めて即結果。`quick`(テスト)・動きを減らす設定ではリーチなし。

### 置き場

`anim.js`: `reachPlan()`(純粋関数、export)、`play()` の中で最後の 1 個の扱いとリーチの段取り、`showResult()` の強化、音(`heartbeat(level)`, `siren()`, `hitstop` 用の強い `clack`, `sad()`)。`style.css`: `.table.reach`, `.reach-l1/2/3`, `.pinch`, `.cutin`, `.lamps`, `.stripes`, `.bolt`, `.rays`, `.impact`, `.spot`, `#stage-overlay.flash-gold`。

## 3. ルール表

- 親機のヘッダーとスマホの画面に `📖 ルール` ボタン。参加画面(名前入力)にもリンク。押すとオーバーレイ(`#rules`)。閉じるは「閉じる」ボタン・背景タップ・Esc。
- 中身(`logic.js` の定数から組み立てる。役の絵は小さな CSS サイコロ、`anim.js` の `PIPS` を使う):

```
┌ ルール ────────────────────────────────┐
│ 強い順                                            │
│ ⚀⚀⚀ ピンゾロ      ×5   いちばん強い              │
│ ⚅⚅⚅ ゾロ目        ×3   2〜6 のゾロ目。大きい数が強い │
│ ⚃⚄⚅ シゴロ        ×2                             │
│ ⚁⚁⚄ 5の目         ×1   同じ数2つ+別の数。6が強く1が弱い │
│ ⚂⚄⚅ 目なし        負け  3回振っても役なし          │
│ ⚀⚁⚂ ヒフミ        負け  2倍払う                  │
│ 🥣→  ションベン    負け  器から飛び出し(たまに)     │
│ 進め方: 親(配信者)が先に振って役を決める → 子が振る。 │
│ 各3投まで。親が負け役なら子は振らずに勝ち。           │
│ 同じ役は引き分けで、両方もう一度。                    │
│ この部屋: 持ち点 100 ・ 1戦 10点 × 倍率 ・ 飲みは 1口 × 倍率 │
│ 例: 親がシゴロ(×2)で勝ち → 子は 20点払う            │
│                                   [ 閉じる ]        │
└───────────────────────────────────────┘
```

- 配信画面用に、親機のアリーナの下へ常時 1 行の順位表 `.legend`(`ピンゾロ ×5 > ゾロ目 ×3 > シゴロ ×2 > 目 ×1 > 目なし > ヒフミ ×2払い`)。表示専用(stage)にもそのまま出る(クローンされる)。

## 4. 履歴

### 対戦中(1〜3 投目)

アリーナの親・子それぞれの役の下に投げた順で並べる(`.throws`):

```
 親  [⚂⚃⚅ 目なし] [⚁⚁⚄ 5の目]
 子  [⚀⚁⚂ ヒフミ]
```

小さな CSS サイコロ + 役名。`shown.state.match[side].throws` から描く(演出が終わるまで古い状態を見せる既存の仕組みに乗る)。非表示(hidden)の子でも出目は見せてよい(名前だけ伏せる)。

### 過去の対戦(直近 30 戦)

- 保存: `state.log`(配列、新しい順、30 件で切る)。結果が出たとき(`finish`)に `logic.js` の `addLog(state, result, { name, now })` で追加。`normalizeState` が配列を補う。1 件 = `{ n(通算の戦数), at, uid, name, round, p:{dice, hand:{type,value,label}}, c:{dice, hand}|null, w: 'parent'|'child', m: 倍率, pt: 動いた点, dr: 飲む回数 }`。出目は決着した投げ(各側の最後の投げ)のもの。
- ルール: `state` は親機だけが書く既存ノードなので変更不要。1 件 ≈ 150 バイト、30 件で ≈ 4.5KB。state の書き込みごとに一緒に送られるが問題ない大きさ。
- 表示: 親機の右側に「対戦の記録」パネル(`data-ref="log"`。順番待ち・ランキングの下)。スマホにも同じパネル(自分の行を黄色で強調)。表示専用にもクローンで出る。1 行:

```
#12  親 ⚃⚃⚅ 6の目  vs  たろう ⚀⚁⚂ ヒフミ  → 親の勝ち ×2  +20点
#11  親 ⚂⚄⚅ 目なし  vs  はなこ(振らず)     → はなこの勝ち  -10点
```

点数の符号は親から見た増減。飲みモードでは `🍺×2` のように表示。

## 5. 持ち点

- 部屋を作る画面に「持ち点」(`choices`: 50 / 100 / 300 / 1000 + 「自由」。自由を押すと数字入力が出る。1〜99999)。`settings.startPoints` に保存。前回の値を記憶(`KEY_SETUP`)。
- `createState(startPoints)` で `host.points` の初期値にする。`normalizeState` は `host.points` が無いときだけ補う(既存の部屋は 100)。
- 画面の `?? 100` をすべて `startPts(settings)`(= `settings.startPoints ?? 100`)に置き換える(親の成績・順番待ち・ランキング・スマホの自分の成績・結果の点数更新)。
- モード選択の説明文「持ち点100から」は選んだ持ち点に追従。ルール表にも出す。
