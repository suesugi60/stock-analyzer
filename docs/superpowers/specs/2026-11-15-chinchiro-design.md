# リスナー対決チンチロ 設計書

作成日: 2026-11-15

## 目的と背景

配信者(利用者)が、配信中にリスナーと1対1でチンチロ(3つのサイコロを器に投げて役を競う)で対決するアプリ。
飲みスゴロク(`sugoroku/`)と同じ見た目のノリ(空色の背景、丸いキャンディ風、昔話キャラ12体、器にサイコロが飛び込む場面)で作る。

利用者が決めたこと:
- リスナーは**自分のスマホ**からリンクを開き、**自分で「振る」を押す**(複数端末をリアルタイムに同期する)。
- 同期の仕組みは **Firebase Realtime Database(無料枠)**。ページは今の GitHub Pages に置く(`/chinchiro/`)。
- 勝ち負けで動くものは **点数制と飲みの両方を用意し、部屋を作るときに選べる**。
- **サイコロの演出にこだわる**。

## ゴール・やらないこと・失敗の定義

ゴール
- 配信画面(親機)に映すだけで、リスナーがQR/URLから参加し、順番に対決できる。
- リスナーが押した「振る」が、全員の画面で同じ演出として同時に流れる。
- 点数(ランキング)または飲み(杯数)で盛り上がる軸ができる。

やらないこと
- ログイン・アカウント(匿名認証のみ)。
- リスナー同士の対決(親は常に配信者)。
- チャット、投げ銭、配信サイトとの連携。
- 複数部屋の同時運営(1配信者=1部屋を想定。コードを変えれば別部屋は作れる)。

こうなったら失敗
- 配信本番でリスナーが「入れない」「押しても反応しない」。
- 親機と子機で出目や勝敗が食い違う。
- リスナーが細工した書き込みで点数や出目を変えられる。

## 制約

- `chinchiro/` 配下の素の HTML/CSS/JS(index.html, style.css, logic.js, art.js, sync.js, anim.js, app.js)+ 設定ファイル `firebase-config.js`。ビルド工程なし。Firebase SDK は CDN(gstatic)から読む。(実装時の変更: 保守のため単一ファイルではなく役割ごとに分けた)
- **この開発環境からは Firebase(gstatic.com / firebaseio.com)に接続できない。** 本物の同期は利用者の環境で確認する。
  開発・テストでは同じ画面を「モック同期(同一ブラウザ内の BroadcastChannel + localStorage)」で動かす。
- 利用者が Firebase プロジェクトを作る作業(無料、10分程度)が一度だけ必要。手順は README に書く。
- 出目はリスナーの端末では決めない(不正防止)。

## ルール(チンチロ)

- サイコロ3個。1回の手番で**3投まで**。役ができた時点で確定。3投しても役なしは「目なし」。
- 親は常に配信者。親が先に振り、役を確定してから子(リスナー)が振る。
- 役の強さ(強い順)と倍率:

| 役 | 出目 | 倍率 | 備考 |
|---|---|---|---|
| ピンゾロ | 1-1-1 | 5 | 最強 |
| ゾロ目(アラシ) | 2-2-2 〜 6-6-6 | 3 | 数字が大きいほど強い |
| シゴロ | 4-5-6 | 2 | |
| 目 | 同じ数2つ + 別の数1つ | 1 | 別の数が「目」。6 > 5 > 4 > 3 > 2 > 1 |
| 目なし | 役なしのまま3投終了 | 負け(1) | |
| ヒフミ | 1-2-3 | 負け(2) | 出た瞬間に手番終了 |
| ションベン | 器から飛び出す | 負け(1) | 出た瞬間に手番終了。毎投 3% の確率で親機が決める |

- 判定: 役の強さで勝敗。**同じ役・同じ目は引き分け → 両者もう一度振る**(ラウンド+1)。
- 親が負け役(目なし・ヒフミ・ションベン)なら、子は振らずに勝ち。
- 支払い倍率 = 勝った側の役の倍率と、負けた側の「罰倍率」(ヒフミ=2、それ以外=1)の大きい方。
  例: 親ゾロ目(3) vs 子目なし(1) → 子が3倍払う。親目5(1) vs 子ヒフミ(2) → 子が2倍払う。子ピンゾロ(5) vs 親目3(1) → 親が5倍払う。

## 点数モードと飲みモード

部屋を作るときに選ぶ: 「点数」「飲み」「両方」。

- 点数: 全員(配信者も)持ち点 100 から。1戦の単位(10 / 20 / 50 点、既定 10)× 支払い倍率を、負けた側から勝った側へ移す。マイナスも許す(「借金」と表示)。配信画面にランキング(上位10人 + 配信者)。
- 飲み: 負けた側が「飲む単位(1口 / 半分 / 1杯、既定 1口)× 支払い倍率」を飲む。結果画面に「○○さん: 1口 × 3 = 3口」と大きく出す。リスナーは各自で飲む(アプリは数えるだけ)。配信者の飲んだ累計も表示。
- 両方: 上の2つを同時に適用。
- 設定は部屋ごとに固定(途中で変えない)。

## 画面

同じ `index.html` が、役割で表示を切り替える。URL に `?room=CODE` があればリスナー/観戦、なければ親機の入口。

### 親機(配信者。配信画面に映す。横長・大きめ)

1. 入口: 「部屋を作る」(名前・キャラ・モード・単位を選ぶ)/「前回の部屋を続ける」。
2. ロビー: 部屋コード(4文字、読み間違えにくい英数字)と QR コード、参加URL。右に順番待ちの列(キャラ・名前・点数)。「対決スタート」で先頭の人と対戦。
3. 対戦: 左に配信者のキャラ、右に挑戦者のキャラ、真ん中に器。手番の側が光る。「振る」ボタン(親の番だけ)。子の番は「○○さんが振るのを待っています」+ 20秒たつと「代わりに振る」ボタン(リスナーが離脱したとき用)。
4. 結果: 役名と倍率を大きく、点数の増減・飲む量、紙吹雪(勝った側のキャラが跳ねる)。「次の挑戦者」「同じ人ともう一回」。
5. 常時: 右上に配信者の成績(○勝○敗、持ち点、飲んだ累計)と消音ボタン。ランキング(点数モード時)。
6. 順番待ちの各行に「飛ばす」「非表示」「ブロック」。ブロックした人は以後参加できない。

```
┌──────────────────────────────────────────────┐
│ 🎲 チンチロ対決   部屋: AB7K  [QR]   🔊  配信者 3勝1敗 120点 │
│                                              │
│  [配信者キャラ]        ( 器 )        [挑戦者キャラ] │
│   ももたろう           ●●●           かっぱ          │
│   目5 (1倍)                        あと2投           │
│                                              │
│ 順番待ち: ①うさ ②たろ ③ねこ …   ランキング: 1.たろ 150 … │
└──────────────────────────────────────────────┘
```

### リスナー(スマホ。縦)

1. 参加: 部屋コード(URLから自動)・名前・キャラ → 「挑戦する」で順番待ちへ。「見るだけ」で観戦。
2. 待機: 「あなたは 3 番目」。親機と同じ対戦の様子(器の演出も同じ)が流れる。
3. 自分の番: 画面が光り、バイブ(対応端末)と音。大きな「振る」ボタン。残り投数。親の役を表示。
4. 結果: 勝敗・役・点数/飲む量。「もう一回並ぶ」「やめる」。
5. 常時: 自分の成績(持ち点・勝敗・飲んだ累計)。

### 観戦

参加しなくても `?room=CODE` を開けば対戦の様子が見える(読み取りのみ)。

### 表示専用(配信ソース用)

`?room=CODE&stage=1` は親機と同じ横長レイアウトから操作ボタンを除いた**表示専用**の画面(読み取りのみ、音なし)。
OBS の「ブラウザソース」などで直接開いて配信に乗せられる。操作は配信者が手元のブラウザ(親機)で行う。
親機の画面をそのまま画面キャプチャして映してもよい(その場合この画面は不要)。

### 同時接続の上限

想定は多くても数十人。無料枠の上限(同時100接続)に近づかないよう、観戦(`?room=` を開いただけの人)が
**80人を超えたら「満員です。配信画面で見てね」と表示して接続しない**。挑戦者(列に並ぶ人)はこの制限の対象外。
接続数は `rooms/{CODE}/presence/{uid}` の数で数える(各端末が自分の分を書き、`onDisconnect` で消す)。

## 同期の仕組み(Firebase Realtime Database)

### 認証と識別

- 全員が匿名認証(`signInAnonymously`)。端末ごとに uid が付き、ブラウザに保持されるので再読み込みしても同じ人として戻れる。
- 親機は「部屋を作った uid」。部屋データに `hostUid` として記録。

### データ構造

```
rooms/{CODE}
  hostUid: string
  createdAt: number
  settings: { mode: 'points'|'drink'|'both', unit: 10|20|50, drinkUnit: 'sip'|'half'|'glass', hostName, hostChar }
  players/{uid}: { name, char, joinedAt, online: bool, points: number, wins, losses, drinks,
                   hidden: bool, banned: bool }     // hidden/banned は親機だけが書く(荒らし対策)
  presence/{uid}: true                                 // 接続中の端末。onDisconnect で消す(人数制限用)
  queue/{uid}: { joinedAt }
  actions/{uid}: { type: 'roll', at }          // リスナーの「振る」要求。親機が処理して削除
  state:
    seq: number                                  // 更新ごとに +1(演出の二重再生防止)
    phase: 'lobby'|'parent'|'child'|'result'
    match: null | {
      childUid, round,
      parent: { throws: [Throw], hand: Hand|null, done: bool },
      child:  { throws: [Throw], hand: Hand|null, done: bool }
    }
    result: null | { winner: 'parent'|'child'|'draw', mult, points, drink, parentHand, childHand }
    host: { points, wins, losses, drinks }
    lastThrow: { by: 'parent'|'child', seq, throw: Throw }   // 演出のトリガー

Throw = { dice: [1-6, 1-6, 1-6], seed: number, shonben: bool, hand: Hand|null, at }
Hand  = { type: 'pinzoro'|'zoro'|'shigoro'|'me'|'none'|'hifumi'|'shonben', value: number, mult: number, label: string, lose: bool }
```

- 親機だけが `state` を書く(ゲームの真実は親機が決める)。
- リスナーは `players/{自分}`・`queue/{自分}`・`actions/{自分}` だけ書ける。
- 親機は `actions/{uid}` を監視し、手番の子からの `roll` が来たら出目を決めて `state` を更新し、`actions/{uid}` を消す。手番でない人の要求は捨てる。
- 点数は `players/{uid}.points` と `state.host.points` に親機が書く(リスナーは自分の `points` を書けない)。
- 荒らし対策: 親機は `players/{uid}.hidden`(名前を「？？？」で表示し、列・ランキングから隠す)と `banned`(列から外し、
  以後「挑戦する」を受け付けない。本人の画面には「参加できません」)を書ける。どちらも全画面が尊重する。

### セキュリティルール(Realtime Database)

```json
{
  "rules": {
    "rooms": {
      "$code": {
        ".read": true,
        "hostUid":   { ".write": "auth != null && !data.exists() && newData.val() == auth.uid" },
        "createdAt": { ".write": "auth != null && !data.exists()" },
        "settings":  { ".write": "auth != null && data.parent().child('hostUid').val() == auth.uid" },
        "state":     { ".write": "auth != null && data.parent().child('hostUid').val() == auth.uid" },
        "players": {
          "$uid": {
            "name":     { ".write": "auth != null && $uid == auth.uid", ".validate": "newData.isString() && newData.val().length <= 12" },
            "char":     { ".write": "auth != null && $uid == auth.uid", ".validate": "newData.isString()" },
            "joinedAt": { ".write": "auth != null && $uid == auth.uid" },
            "online":   { ".write": "auth != null && $uid == auth.uid" },
            "$other":   { ".write": "auth != null && data.parent().parent().parent().child('hostUid').val() == auth.uid" }
          }
        },
        "presence": { "$uid": { ".write": "auth != null && $uid == auth.uid" } },
        "queue":   { "$uid": { ".write": "auth != null && ($uid == auth.uid || data.parent().parent().child('hostUid').val() == auth.uid)" } },
        "actions": { "$uid": { ".write": "auth != null && ($uid == auth.uid || data.parent().parent().child('hostUid').val() == auth.uid)" } }
      }
    }
  }
}
```

ルールの意図: 親機以外は出目・勝敗・点数を書けない。リスナーは自分の名前・キャラ・順番待ち・「振る」要求だけ。
(ルールの文面は実装時に Firebase のシミュレーターで検証する。細部の修正は作り手に任せる。)

### 出目の決定と演出の同期

- 出目は親機が `Math.random`(または `crypto.getRandomValues`)で決め、`seed`(演出用の乱数の種)と一緒に `state.lastThrow` に書く。
- 各端末は `lastThrow.seq` が増えたら、その `dice` と `seed` から**同じ演出**を再生する(演出の乱数は seed から作る疑似乱数だけを使う)。
- 端末間の開始時刻は通信の遅れで最大1秒ほどずれるが、同じ映像が流れる。
- 自分の端末で「振る」を押したときは、要求を送ると同時に「手の中でサイコロを振る」待ち演出を始め、`lastThrow` が来たら投げる。

### 切断・復帰

- 親機: 再読み込みしても `localStorage` の部屋コードと匿名 uid で親機に戻る。親機が閉じている間、子の「振る」は処理されない(「配信者の画面を待っています」と表示)。
- リスナー: `onDisconnect` で `players/{uid}.online=false`。順番待ちには残す。親機はオフラインの人に印を付け、「飛ばす」ボタンで列から外せる。手番中に20秒反応がなければ親機が「代わりに振る」。
- 親機の「部屋を閉じる」で `state.phase='closed'`。リスナーには「終了しました」。

## サイコロの演出(こだわり)

全端末で同じ映像になるよう、乱数はすべて `seed` 由来。音はその場で合成(WebAudio)。消音ボタンあり。`prefers-reduced-motion` では結果だけ表示。

1. **構え**(0.6秒): 振る人のキャラの横で、手の中でサイコロ3つがカラカラ鳴る(小刻みな揺れ + ざらついた音)。
2. **投げ込み**(0.3秒): 3つのサイコロが振る人の側から、少しずつずれたタイミング(0 / 80 / 160ms)と違う弧で器に飛び込む。CSSの立方体(6面)が3D回転。
3. **跳ねる**(1.2秒): 器の内壁に沿って各サイコロが3〜4回跳ねる。高さは徐々に下がり、位置は seed で決める(互いに重ならない)。跳ねるたびに「カッ」(音程をばらす)。最初の衝突で器の縁が小さく揺れる。
4. **止まる**: 1つずつ順に止まる。すでに2つが同じ数で、最後の1つが役を決めるときは、最後の跳ねを**スローモーション**(0.4倍速)にして少し寄る(拡大1.1倍)。止まった面が出目。
5. **役の演出**(1秒):
   - ピンゾロ: 画面が金色にフラッシュ、星の粒が弾け、「ピンゾロ!!」が震えながら出る。高い鐘の音。
   - ゾロ目: 虹色のリングが広がり「○ゾロ!」。
   - シゴロ: 青い火花と「シゴロ!」。
   - 目: 余った1つのサイコロが脈打ち、「○の目」。数字が大きいほど派手。
   - 目なし: 灰色の「目なし… あと○投」。小さく落ち込む音。
   - ヒフミ: 画面が暗くなり赤い「ヒフミ…」と雷鳴の音。
   - ションベン: 1つのサイコロが縁を越えて外へ跳び出し、机をコロコロ転がって画面外へ。「ションベン!」のスタンプ。
6. **対決の結果**: 勝った側のキャラが跳ね、負けた側が青ざめる。倍率は「×3」のスタンプで。点数の増減はカウントアップで動く。紙吹雪。

## 技術構成

- `chinchiro/` の各ファイル。構成は飲みスゴロクと同じ3層(実装ではファイルを分けた。計画書の「ファイル構成」を参照):
  1. `<script id="chinchiro-logic">`: 役の判定・比較・支払い、部屋状態の遷移(純粋関数。`state` を受け取り新しい `state` を返す)。
  2. 絵(キャラ12体・サイコロ・器): 飲みスゴロクの `SugorokuArt` を複製して使う(別ファイル参照にはしない)。
  3. 表示層 + 同期アダプタ。
- 同期アダプタの口: `createRoom / watch(path, cb) / set / update / remove / onDisconnectSet / uid()`。
  実装は2つ: `firebase`(本番)と `mock`(`?mock=1`。同一ブラウザ内で BroadcastChannel + localStorage)。
- `chinchiro/firebase-config.js`: `window.FIREBASE_CONFIG = {...}` を利用者の値で置く。無い/空ならトップに案内を出す。
- QR コードは CDN のライブラリで描く。読めなければ URL とコードだけ大きく出す(QRは必須ではない)。
- `chinchiro/README.md`: 遊び方と Firebase の準備手順(下記)。

### テスト

- ロジック(`node --test`): 役の判定(全パターン)、比較と引き分け、支払い倍率、状態遷移(親→子→結果、3投制限、親の負け役で子は振らない、引き分けで再戦、代わりに振る)。
- 画面(Playwright、`?mock=1`、ローカルHTTPサーバー経由): 親機が部屋を作る → 別ページでリスナーが参加 → 列に並ぶ → 対決 → 親が振る → リスナーが振る → 両画面に同じ出目と結果 → 点数が動く。演出はタップで飛ばせることも確認。
- 本物の Firebase はこの環境から繋げないため、利用者の環境での動作確認を最後に行う(手順を README に書く)。

## 導入手順(利用者がやること。README に載せる)

1. https://console.firebase.google.com で「プロジェクトを追加」(名前は何でも。Google アナリティクスはオフでよい)。
2. 左の「構築」→ Authentication → 始める → 「匿名」を有効にして保存。
3. 「構築」→ Realtime Database → データベースを作成 → ロケーションは `asia-southeast1` → 「ロックモード」で作成。
   作成後「ルール」タブに、上記ルールを貼り付けて「公開」。
4. Authentication → 設定 → 承認済みドメイン に `suesugi60.github.io` を追加。
5. 歯車 → プロジェクトの設定 → 「マイアプリ」→ ウェブ(</>)→ 名前を付けて登録 → 表示される `firebaseConfig = { ... }` をコピーして、`chinchiro/firebase-config.js` に貼る(この値は公開してよいもの)。
6. `main` に反映すると `https://suesugi60.github.io/stock-analyzer/chinchiro/` で動く。

無料枠(Spark)の範囲: 同時接続 100、転送 10GB/月。この用途では十分。

## レビューで決めたこと(2026-11-15)

- 配信への映し方: 配信者が操作するブラウザをそのまま映す前提。加えて OBS ブラウザソース用の表示専用画面(`&stage=1`)を用意する。
- 同時接続: 想定は数十人。観戦者が80人を超えたら満員表示にして接続しない(無料枠100接続の安全装置)。
- 荒らし対策: 親機から「非表示」「ブロック」ができる(`hidden` / `banned`)。

## 作り手に任せること

- 画面の細かい配置・色・文言(飲みスゴロクのトーンに合わせる)。
- 演出のタイミングの微調整、音の作り方。
- ルール文面の細部(Firebase のシミュレーターで検証して直す)。
- オフライン判定の秒数、代わりに振るまでの秒数(20秒を目安)。
- モック同期の実装方法。
