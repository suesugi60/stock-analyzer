# 楽天トラベル領収書一括ダウンロード 設計書

作成日: 2026-11-10

## 目的

楽天トラベルの過去の国内宿泊予約について、領収書を1件ずつ手で発行・保存する手間をなくし、
まとめて PDF として保存できるようにする。宛名は全件同じ(経費精算・確定申告などの用途)。

本リポジトリ(stock-analyzer)は株式分析ツールだが、`sugoroku/` と同じく
`rakuten_receipts/` サブフォルダに同居させる。既存コードとは一切共有しない。

## 決定事項(利用者との合意)

| 項目 | 決定 |
|---|---|
| 宛名 | 全件同じ。実行時に指定する |
| 実行環境 | 利用者の Mac。ターミナルからコマンドで実行 |
| 方式 | Python + Playwright で Chrome を自動操作する |
| ログイン | 利用者が画面上で手動で行う。パスワードはスクリプトに渡さない |
| 対象 | 国内宿泊・オンラインカード決済の予約のみ |
| 置き場所 | `rakuten_receipts/`(公開リポジトリなのでコードだけを置く) |
| 出力先 | `~/Documents/rakuten-receipts/`(リポジトリの外) |
| 安全策 | 1件目は発行直前で止めて人が確認。宛名の修正機能は使わない |

対象外: 楽パック、レンタカー、海外宿泊、バス、現地決済の予約(現地決済は宿が発行する)。

## 前提(楽天トラベル公式ヘルプより)

出典: https://travel.faq.rakuten.net/detail/000003579
(作成環境からはこのページを直接開けず、検索結果に出た要約で確認した。実装前に利用者が原文と見比べること。)

- 手順は「【予約確認】で国内宿泊を選ぶ → 対象予約の『領収書発行』 → 宛名入力画面で宛名を指定し
  『領収書の発行』 → 宛名確認画面で『発行する』 → 印刷またはデータ保存」。
- 宛名は50文字まで。環境依存文字(㈱ ㈲ 髙 﨑 など)、特殊記号(♪ 〒 など)、半角記号(! ( など)は使えない。
- 敬称は「様」か「御中」。
- **宛名の修正は1回限り**。ほかの記載内容は変更できない。
- 楽天トラベルが発行するのはオンラインカード決済の予約だけ。

## 未確認の点と、その扱い

このツールは、作成者(Claude)がログイン後の画面を一度も見られないまま作る。
そのため次の点は推測であり、利用者の Mac での初回実行で確かめる。

| 未確認の点 | 扱い |
|---|---|
| 過去の予約一覧の画面構造 | 公式ヘルプに出てくる文言(「領収書発行」など)を手がかりに要素を探す。見つからなければ診断ファイルを残して止まる |
| 予約一覧ページの URL | 決め打ちしない。一覧ページまでは利用者が手で開く(後述) |
| 発行後の領収書の形式 | PDF ファイルのダウンロードと、印刷用ページの両方に対応する |
| 発行済みの予約で「領収書発行」を押したときの挙動 | 修正らしい画面なら何も入力せず「要確認」にする(後述) |
| 自動操作のブラウザでログインできるか | 拒否された場合、回避策は講じない。方式を見直す |
| 楽天の規約が自動操作を禁じているか | 確認できていない。人と同じ手順を低頻度でたどるにとどめ、利用は利用者の判断とする |

確認済みの点: 画面付き(ヘッドレスでない)Chromium でも `page.pdf()` は動く(Playwright 1.63 で検証)。

## 使い方

コマンドは2つ。リポジトリのルートで実行する。

```bash
python -m rakuten_receipts list --from 2025-01-01 --to 2025-12-31
python -m rakuten_receipts download --from 2025-01-01 --to 2025-12-31 --name "株式会社サンプル" --title 御中
```

| 引数 | 対象 | 意味 |
|---|---|---|
| `--from` / `--to` | 両方 | チェックイン日での絞り込み(両端を含む)。省略すると履歴にある全件 |
| `--out` | 両方 | 出力先。既定は `~/Documents/rakuten-receipts/` |
| `--name` | download | 宛名。必須 |
| `--title` | download | 敬称。`様` か `御中`。必須(誤った既定値で発行しないよう、既定値は置かない) |
| `--limit` | download | 今回処理する最大件数(要確認・失敗になった予約も1件と数える) |

### 共通の流れ(ブラウザの起動から一覧の読み取りまで)

1. 専用プロファイルで Chrome を画面付きで起動し、楽天トラベルのトップページを開く。
2. ターミナルに「ログインして、予約確認の国内宿泊で過去の予約一覧を表示したら Enter を押してください」と出す。
3. Enter を受けたら、開いているタブから予約一覧のタブを見つけ、次ページをたどりながら全件を読む。
4. 結果を台帳(`receipts.csv`)に反映し、画面に表で出す。

`list` はここで終わる。サイト上の状態は何も変えない。

### `download` の流れ

1. 起動前に宛名を検証する(後述)。問題があればブラウザを開かずに終了する。
2. 共通の流れで一覧を読み直す。
3. 対象(期間内、「領収書発行」がある、台帳で取得済みでない)を表で出す。0件なら終了。
4. **人による確認**: 「領収書発行」→ 宛名入力 →「領収書の発行」と進み、今回の実行で最初に宛名確認画面まで
   到達した予約で**停止**する。確認画面から読み取った宛名を表示し、
   「ブラウザの確認画面を見て、この内容で発行しますか? [y/N]」と聞く。`y` 以外なら何も発行せずに終了する。
5. `y` なら「発行する」を押し、領収書を PDF で保存して台帳に記録する。
6. 残りがあれば保存先を示し、「PDF を開いて確認してください。残り N 件を続けますか? [y/N]」と聞く。
   `y` 以外ならそこで終了する。
7. 残りは人の確認なしで1件ずつ処理する。各件の間は 3〜6 秒空ける。並列には処理しない。
8. 最後に、取得・要確認・失敗の件数と台帳の場所を出す。

## 安全策

宛名の修正が1回限りなので、「間違った宛名で発行しない」「修正の権利を勝手に使わない」を最優先にする。
迷ったら何も押さない(フェイルクローズ)。

- **画面の判定**: 各手順の前に、今の画面が想定どおりか(宛名入力・宛名確認・領収書表示のどれか)を判定する。
  判定できなければ何も押さず、その予約を「要確認」にして次へ進む。
- **宛名の照合**: 全件で、宛名確認画面の本文に指定した宛名と敬称がそのまま出ている場合だけ「発行する」を押す。
  空白の違いは無視する。それ以外の不一致は「要確認」。人による確認(前述)は、この照合に加えて行う。
- **修正機能は使わない**: 「領収書発行」を押した先が修正・再発行らしい画面(「修正」「再発行」「発行済」などの文言がある)なら、
  宛名を入力せず「要確認」にする。領収書がそのまま表示された場合は、その内容のまま保存し、
  台帳のメモに「発行済みを再表示」と残す(宛名は指定したものと違う可能性がある)。
- **連続失敗で中止**: 「要確認」または「失敗」が3件続いたら、画面構成が想定と違うとみなして全体を止める。
- **発行後の失敗を区別する**: 「発行する」を押した後で保存に失敗した場合は「失敗(発行後)」と記録する。
  保存できない発行を重ねないよう、何件目であってもそこで実行を止め、ブラウザを開いたままにして手で保存できるようにする。
- **検出回避はしない**: 自動操作であることを隠す細工は入れない。

## 保存形式

出力先(既定 `~/Documents/rakuten-receipts/`)に次を置く。

- **PDF**: `2025-03-15_ホテル名_予約番号.pdf`。日付はチェックイン日。
  施設名はファイル名に使えない文字(`/ \ : * ? " < > |`、制御文字)と空白の並びを `_` に置き換え、60文字で切る。
  同名のファイルがすでにある場合は上書きせず、末尾に `_2` のように番号を付ける。
- **台帳**: `receipts.csv`(BOM 付き UTF-8。Excel でそのまま開ける)。
  列は 予約番号・施設名・チェックイン・チェックアウト・金額・状態・ファイル名・更新日時・メモ。
- **診断ファイル**: `debug/` に、失敗した画面のスクリーンショットと HTML。

状態の値:

| 状態 | 意味 | 次回の `download` で |
|---|---|---|
| 未取得 | 一覧にあり、「領収書発行」がある | 対象 |
| 取得済み | PDF を保存した | 飛ばす |
| 対象外 | 「領収書発行」がない(現地決済など) | 飛ばす |
| 要確認 | 想定外の画面だったので何もしなかった | 対象(再挑戦) |
| 失敗 | 発行前の段階でエラー | 対象(再挑戦) |
| 失敗(発行後) | 発行は済んだ可能性があるが保存できなかった | 対象(発行済みの扱いになる) |

台帳は1件処理するたびに書き出す。途中で止めても、そこまでの結果は残る。

ログイン状態を持つブラウザのプロファイルは `~/Library/Application Support/rakuten-receipts/profile` に置く。
`~/Documents` は iCloud で同期されることがあるため、そこには置かない。

`--out` がこのリポジトリの中を指している場合はエラーにする(公開リポジトリに領収書を置かないため)。

## 構成

```
rakuten_receipts/
├── README.md            セットアップと使い方、注意点
├── requirements.txt     playwright のみ
├── requirements-dev.txt pytest
├── __init__.py
├── __main__.py          python -m rakuten_receipts の入口
├── cli.py               引数の解釈と入力確認(y/N)
├── runner.py            list / download の進行。安全策の判断はここに集める
├── browser.py           Chrome の起動(専用プロファイル)、一覧タブの特定
├── site.py              楽天の画面操作。セレクタと画面の文言はここだけに置く
├── ledger.py            receipts.csv の読み書きと、対象の選び出し
├── naming.py            ファイル名の生成、宛名の検証
├── models.py            Reservation などのデータ型
└── tests/
    ├── fixtures/        楽天の画面を模したダミー HTML
    ├── test_naming.py
    ├── test_ledger.py
    ├── test_runner.py
    └── test_site.py
```

ルートの `requirements.txt` は変更しない(Streamlit Community Cloud のデプロイに使われているため)。

### 各部品の責任

- **`site.py`**: 画面を読む・押すだけを担う。判断はしない。主な関数は次のとおり。
  - `detect_screen(page)` → `LIST` / `ADDRESSEE_INPUT` / `ADDRESSEE_FIX` / `CONFIRM` / `RECEIPT` / `LOGIN` / `UNKNOWN`
  - `read_reservations(page)` → 全ページ分の `Reservation` のリスト
  - `open_receipt(page, reservation)`、`fill_addressee(page, name, title)`、`go_to_confirm(page)`
  - `read_confirm_text(page)`、`submit_issue(page)`、`save_receipt(page, path)`
  - 想定した要素がなければ `UnexpectedScreen` を送出する。
- **`runner.py`**: `site.py` の関数を順に呼び、安全策(照合・フェイルクローズ・連続失敗の中止)を判断する。
  画面操作を直接は持たないので、偽の `site` を差し込んでテストできる。
- **`ledger.py`**: 台帳の更新規則を担う。一覧の読み直しで「取得済み」を「未取得」に戻さない。
- **`naming.py`**: ブラウザに依存しない純粋な関数。
- **`browser.py`**: `channel="chrome"`(インストール済みの Google Chrome)で起動する。
  なければ Playwright 同梱の Chromium を使う。

### 画面の読み取り方(暫定)

ログイン後の画面を見られないため、CSS クラスには頼らず、公式ヘルプに出てくる文言で要素を探す。

- 一覧: 「領収書発行」と書かれたリンクまたはボタンを起点に、その予約のまとまり(予約番号を1つだけ含む最も近い親要素)を特定する。
  まとまりの中から、予約番号(「予約番号」の直後の文字列)、日付、施設名、金額(`円`)を取り出す。
  予約番号はあるが「領収書発行」がないまとまりは「対象外」とする。次ページは「次」を含むリンクでたどる。
- 宛名入力: 宛名の入力欄、敬称(「様」「御中」)の選択、「領収書の発行」ボタン。
- 宛名確認: 「発行する」ボタン。
- 領収書: 「発行する」を押した結果、ダウンロードが始まればそのファイルを保存する。
  ページ(同じタブまたは新しいタブ)が開けば、印刷用の表示にして `page.pdf()` で A4 の PDF にする。

実際の画面と合わない箇所は、初回実行の診断ファイルをもとに `site.py` だけを直す。

### 宛名の検証

起動前に次を確かめ、該当すれば理由を示して終了する。サイト側の検証の代わりではなく、無駄な操作を防ぐためのもの。

- 空、または50文字を超える
- 半角記号(ASCII の記号)を含む
- 環境依存文字や特殊記号を含む(㈱ ㈲ 髙 﨑 ♪ 〒、および囲み文字・組文字の範囲)

## エラー処理

- 想定した要素が時間内に見つからない → 診断ファイルを保存し、その予約を「要確認」(発行前)または「失敗(発行後)」にする。
- 処理の途中でログイン画面に戻された → ターミナルで再ログインを求め、その予約を1回だけやり直す。
- 一覧を1件も読めない → 診断ファイルを保存して終了する(台帳は変更しない)。
- Ctrl+C → 処理中の予約は台帳を変更せず終了する。

診断ファイルには氏名・予約番号・金額などが含まれる。Mac の中に保存するだけで、どこにも送らない。
作成者に見せる範囲は利用者が選ぶ。README に「公開リポジトリにコミットしない」と明記する。

## テスト

本物の楽天の画面ではテストできない。テストが保証するのは「想定した画面構成に対して正しく動くこと」まで。

### 単体(`pytest`)

- `naming`: ファイル名の生成(禁止文字、長い施設名、日付なし、同名の回避)、宛名の検証(各拒否理由と正常系)。
- `ledger`: 新規追加、読み直しで取得済みを保つ、対象の選び出し(期間・状態)、BOM 付き UTF-8 での往復。
- `runner`(偽の `site` を使用):
  - 1件目の確認で `N` → `submit_issue` が呼ばれない。
  - 確認画面の宛名が不一致 → `submit_issue` が呼ばれず「要確認」。
  - 修正らしい画面 → `fill_addressee` が呼ばれず「要確認」。
  - 3件連続の失敗で中止。
  - 発行後の保存失敗 → 「失敗(発行後)」。
  - `--limit` と期間の絞り込み。

### 画面(`pytest` + Playwright、ダミーページ)

`tests/fixtures/` に、一覧(2ページ、オンライン決済と現地決済が混在)、宛名入力、宛名確認、領収書、
修正らしい画面、想定外の画面を用意する。

- 一覧を2ページ分読み、対象と対象外を正しく分ける。
- 発行の一連の操作で PDF が保存される(印刷用ページ版と、ダウンロード版の両方)。
- 想定外の画面で `UnexpectedScreen` になり、診断ファイルが残る。

### 利用者の Mac での確認(手順として README に書く)

1. `list` を実行し、台帳の内容が実際の履歴と合うか見る。
2. `download --limit 1` で1件だけ発行し、PDF の内容を見る。
3. 問題なければ残りを実行する。

## 追記(2026-11-10): 領収書まとめ.pdf

利用者の要望で、全部の領収書を1つにまとめた PDF も出力する。

- **出すもの**: 出力先に `領収書まとめ.pdf`。台帳で「取得済み」になっている領収書を、チェックイン日の古い順
  (日付不明は最後、同じ日は予約番号順)に結合する。個別の PDF はそのまま残す。
- **いつ作るか**: `download` の最後に毎回作り直す(途中で止めた場合も、そこまでの取得済みで作る)。
  ブラウザを開かずに作り直す `merge` コマンドも用意する。

  ```bash
  python -m rakuten_receipts merge
  ```

- **範囲**: 出力先フォルダの台帳にある取得済みの全件。`--from` / `--to` では絞らない。
  年ごとに分けたいときは `--out` を分ける。
- **しおり**: 領収書ごとに「チェックイン日 施設名」のしおりを付け、PDF ビューアで目的の領収書へ飛べるようにする。
- **欠けているファイル**: 台帳にあるのにファイルが見つからない・PDF として読めないものは飛ばし、予約番号を表示する。
  結合全体は止めない。
- **1件もないとき**: ファイルを作らない(以前のまとめファイルがあっても消さない)。
- **書き込み**: 一時ファイルに書いてから置き換える。以前の `領収書まとめ.pdf` は上書きする(台帳から作り直せるため)。
- **依存**: PDF の結合に `pypdf` を使う(`rakuten_receipts/requirements.txt` に追加)。
- **構成**: `rakuten_receipts/merge.py` に置く。ブラウザには触らない。

## 追記(2026-11-10): レビュー後の変更

実装後のレビューで見つかった問題への対応。上の本文と食い違う箇所は、この追記を正とする。

- **発行済みかもしれない予約には二度と入力しない。** 発行につながりうるクリック(「領収書の発行」「発行する」)の前に、
  台帳へ「失敗(発行後)」を先に書く。確認画面に着いたら(まだ発行されていないので)元に戻す。
  これにより、保存の失敗だけでなく、Ctrl+C・クラッシュ・台帳の書き込み失敗でも「発行済みかもしれない」が残る。
  本文の「Ctrl+C → 台帳を変更せず終了」は、発行につながるクリックより前に限る。
- **「失敗(発行後)」の予約のやり直し**: 領収書がそのまま表示されたときだけ保存する。入力画面が出ても入力せず、
  状態も下げない(修正の画面かもしれないため)。片付けは利用者が台帳を直して行う。
- **人の確認は最初の1件で2回。** 宛名を入力した直後(「領収書の発行」を押す前)と、確認画面(「発行する」を押す前)。
  サイトが確認画面を出さずに発行する作りだった場合でも、人の確認なしに発行しないため。
- **確認画面なしで発行された場合**: 保存して「取得済み」にし、残りも同じように進めるかを聞く。
- **「領収書の発行」の後に分からない画面が出た場合**: 発行されたかもしれないので「失敗(発行後)」にして止まる。
  入力欄のある画面が出た場合は未発行とみなして「要確認」。ログイン画面なら、ログインし直して1回やり直す。
- **人の確認で見せるもの**: 指定した宛名ではなく、確認画面から読み取った行。
- **宛名の照合**: 宛名の直後に(空白・「敬称」の見出し・コロンだけを挟んで)敬称が続く場合だけ一致。
  宛名の前後に別の文字が続く長い宛名は不一致。本文の「既知の限界」はこれで大半が解消する。
  残る限界: 宛名が宿泊者氏名と同じで、確認画面の宛名が空欄だった場合、宿泊者の行で一致とみなしうる。
- **修正・再発行の目印**: 本文中の「再発行」「発行済」、ボタン・リンク・見出しの「修正」「変更」「訂正」
  (サイト共通のヘッダーやナビの中は除く)。目印があれば、「発行する」があっても確認画面とみなさない。
  宛名欄に最初から値が入っている画面にも入力しない。
- **画面を待つ**: クリック後は、分かる画面になるまで待つ。「発行する」の後は、領収書かダウンロードが出るまで最長30秒待つ。
- **ダウンロードの検査**: PDF でないファイルは領収書として保存しない。
- **台帳**: 読めない台帳(文字コード不明、必須の列がない)は上書きせずに止まり、ブラウザも開かない。Shift_JIS は読める。
  利用者が書いた未知の「状態」は残し、発行の対象から外す。
- **`--out` の制限**: `.git` の有無に関係なく、ツールを置いたフォルダの中は指定できない。
  `.gitignore` に出力ファイルの名前を足し、二重に防ぐ。
- **`list` の表示**: `--from` / `--to` の範囲だけを表示する(台帳には読めた全件を入れる)。
- **ページ送り**: 新しい予約が増えないページに来たら終わる。
- **入力を受け取れない端末**: 確認には「いいえ」として扱い、Enter 待ちでは説明を出して終了する。
- **ダミーページ**: 本文に「テスト用のダミー」と明記する。

## 追記(2026-11-10): 案内モードと起動スクリプト

利用者の要望(もっと楽に実行したい)で、1行で始められる入口を足す。既存の `list` / `download` / `merge` は変えない。

- **起動スクリプト `rakuten_receipts/start.sh`**: どこから実行してもよい。初回だけ `.venv` を作って依存を入れ、
  Mac に Google Chrome がなければ Playwright の Chromium も入れる。そのあと案内モードを起動する。
  Python がない・古い場合は、何をすればよいかを日本語で出して終了する。
- **案内モード `guide`**: 宛名・敬称(1: 様 / 2: 御中)・期間(空で全件、`2025` で1年分、`2025-01-01 2025-03-31` で期間)を
  質問で受け取る。読み取れない答えは理由を示して聞き直し、5回だめなら終了する。
  質問はブラウザを開く前に済ませる。
- **一覧の自動検知**: Enter を待たず、予約一覧のタブが現れて2秒そのまま表示され続けたら読み始める
  (移動の途中で通り過ぎる画面を拾わないため)。最長10分待ち、現れなければ画面の記録を残して終了する。
- **発行を始める前の確認**: `list` を別に実行して目で確かめる段階がなくなる代わりに、対象の一覧を出して
  「この N 件の領収書を発行します。一覧はこれで合っていますか?」と聞く。`y` 以外なら何も発行しない。
  最初の1件での2回の確認と、残りを続けるかの確認は、そのまま残す。
- **終了時**: 1回の起動・1回のログインで、発行からまとめ PDF の作成まで進む。保存したものがあれば出力フォルダを Finder で開く。
