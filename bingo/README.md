# 配信用ビンゴ

TikTokなどのライブ配信で、主催者(配信者)とリスナーが遊ぶビンゴです。

- リスナーはURLを開くだけで参加できます。登録もアプリのインストールも要りません。
- カードは、リスナーが枚数を申請し、主催者が許可した分だけ配られます。1人何枚でも配れます。
- 主催者が番号を発表すると、全員のカードに自動で穴が開き、リーチとビンゴも自動で判定されます。

このリポジトリは株式分析ツールですが、スゴロクと同じく `bingo/` に同居させています。ほかのコードとは共有しません。

> 設計の経緯は `docs/superpowers/specs/2026-11-13-bingo-design.md` にあります。

## 2つの画面

| 画面 | URL | 使う人 |
|---|---|---|
| リスナー画面 | `https://bingo.○○.workers.dev/` | リスナー全員。このURLを配信で案内する |
| 主催者画面 | `https://bingo.○○.workers.dev/host` | 主催者だけ。合言葉が必要 |

`○○` は、Cloudflareのアカウントを作るときに決める名前です。

## 遊び方

### 主催者

1. 主催者画面を開き、合言葉を入れる。ブラウザが覚えるので、次からは入れ直さなくてよい。
2. 配信を始めたら「締め切り中(押すと受付を始める)」を押して、受付を始める。
3. リスナーから申請が届くと「申請」に並ぶ。枚数は `−` `＋` で変えられる。「許可」で配る。「却下」で見送る。
   まとめて配るときは「すべて許可」。
   申請が1件片づいた直後は、押し間違いを防ぐため、許可と却下のボタンが一瞬だけ押せなくなる。
4. 番号を発表する。
   - アプリに引かせるとき: 「ランダムに引く」。
   - 自分で引いたとき(抽選機など): 盤面の番号を押す。
   - 押し間違えたら「直前の番号を取り消す」。繰り返すと新しい順に1つずつ戻る。
5. 「ビンゴ」に、達成した順で名前が並ぶ。同じ番号で同時にそろった人は同じ順位になる。
   一覧に出るのは先着100枚まで(ビンゴしたカードの合計は、一覧の上に出る)。
6. ビンゴが出てもゲームは続く。終わりどきは主催者が決める。
7. 続けて遊ぶとき:
   - 「次のゲーム(カードはそのまま)」: 番号とビンゴの記録だけ消す。
   - 「すべてリセット」: カード・申請・参加者もすべて消す。リスナーは申請からやり直す。

荒らしは「ブロック」できます。その人のカードは消え、以後の申請も届きません。「解除」で戻せます(カードは戻りません)。

### リスナー

1. URLを開き、名前とほしい枚数(1回に50枚まで)を入れて「申請する」。
2. 主催者が許可するとカードが届く。
3. あとは見ているだけ。番号が発表されると穴が開く。リーチのマスは点線で光り、ビンゴすると画面いっぱいに知らせる。
4. もっとほしいときは「追加で申請する」。

配信を見るためにTikTokへ戻っても、カードは消えません。ビンゴのページに戻ると、その間に出た番号がまとめて反映されます。

## 配信で使うときのコツ

- **URLの案内**: TikTokのライブのコメントに貼ったURLはタップできません。プロフィールのリンクに置くか、短いURLを画面に出して読み上げてください。
- **主催者画面は別の端末で**: 配信しているスマホで主催者画面を開くと、配信が止まることがあります。PCや2台目のスマホで開いてください。複数の端末で同時に開いても大丈夫です。
- **反映の遅れ**: 配信の映像は数秒遅れてリスナーに届きます。そのままだと、リスナーの画面が配信より先に動いてネタバレになります。
  主催者画面の「リスナーへの反映」で、遅らせる秒数を選べます(3〜30秒)。実際の遅れは配信ごとに違うので、
  リハーサルで自分の配信を別の端末で見ながら合わせてください。主催者画面には遅れなしで出ます。
- **引き継ぎリンク**: カードは「開いたブラウザ」に保存されます。プロフィールのリンクから開くとTikTok内のブラウザになり、
  あとでSafariやChromeで開き直すと別人として扱われます。リスナー画面の下にある「引き継ぎリンクをコピー」で、
  同じカードを別のブラウザに持っていけます。リスナーが「カードが消えた」と言ったら、これを案内してください。
  このリンクを人に渡すと、その人も同じカードを見られます。
- **本番の前に一度通す**: 自分のスマホで、プロフィールのリンクから開く → 申請 → 許可 → 番号を出す → TikTokに戻る → ビンゴのページに戻る、
  までを一度試してください。TikTok内のブラウザでカードが保存され続けるかは、開発時には確かめられていません。

## できないこと

- **本人確認**: 名前は自己申告です。申請者が本当にそのTikTokアカウントの人かは確かめられません。
- **TikTokとの自動連動**: コメントやギフトを読み取ることはできません。許可は主催者の手作業です。
- **申請を止めること**: URLを知っていれば誰でも申請を送れます。大量の申請は、許可制・受付の締め切り・ブロックで防ぎます。
- **複数の部屋**: 部屋は1つだけです。
- **ブロックの抜け道をふさぐこと**: ブロックは端末(ブラウザ)単位です。ブラウザのデータを消せば、別人として申請し直せます。主催者の許可で止めてください。

## ギフトと景品について

カードの枚数をギフトと引き換えにして景品を出す形は、TikTokの賭博に関する規約や、日本の法律(賭博・富くじ)に触れるおそれがあります。
その形で行う場合は、事前に規約と法律を確認してください。

## 公開のしかた(Cloudflare)

Cloudflare Workers の無料プランで動きます。
画面の文言は変わることがあります。迷ったら公式の説明([Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/))を見てください。

### 1. アカウントを作る

1. <https://dash.cloudflare.com/sign-up> でアカウントを作る。
2. 左のメニューから **Workers & Pages** を開く。初回に `○○.workers.dev` の `○○` を決める画面が出る。
   これがビンゴのURLの一部になるので、短く覚えやすいものにする。あとから **Your subdomain** の **Change** で変えられる。

### 2. GitHubのリポジトリをつなぐ

1. **Workers & Pages** で **Create application** を押す。
2. **GitHub** を選び、GitHubにログインしてCloudflareに `suesugi60/stock-analyzer` へのアクセスを許可する。
3. リポジトリ `stock-analyzer` を選ぶ。
4. 設定を次のとおりにする。

   | 項目 | 値 |
   |---|---|
   | Project name(Workerの名前) | `bingo` (`wrangler.jsonc` の `name` と同じにする。違うとビルドが失敗する) |
   | Production branch | `main` |
   | Root directory(詳細設定の中) | `bingo` |
   | Build command | 空のまま |
   | Deploy command | `npx wrangler deploy` (初期値のまま) |

5. **Save and Deploy** を押す。数分で公開される。以後は `main` を更新するたびに自動で公開される。
6. 本番以外のブランチのビルド(**Enable Preview Builds**)はオフにしておく。このアプリでは使わない。

### 3. 合言葉を設定する

合言葉を設定するまで、主催者画面には誰も入れません。

1. **Workers & Pages** → `bingo` → **Settings** → **Variables and Secrets** → **Add**。
2. **Type** は **Secret**、**Variable name** は `HOST_PASSWORD`、**Value** に合言葉を入れる。
3. **Deploy** を押す。

合言葉は12文字以上の、推測されにくいものにしてください。合言葉を5回続けて間違えると、その接続元(同じWi-Fiなど)からは5分間、新しく入れなくなります。
すでに入っている主催者画面は、そのまま使えます。
設定した合言葉は、次の自動公開でも消えません。

### 4. 確かめる

1. `https://bingo.○○.workers.dev/host` を開き、合言葉で入れること。
2. `https://bingo.○○.workers.dev/` をスマホで開き、申請 → 許可 → 番号の発表まで通ること。

## 上限と無料枠

アプリ側の上限:

| 項目 | 上限 |
|---|---|
| 名前 | 20文字 |
| 1回の申請 | 50枚(許可されたあと、何度でも追加で申請できる) |
| 部屋全体のカード | 5,000枚 |
| 許可待ちの申請 | 1,000件 |

Cloudflare無料プランの上限(2026年11月時点。最新は[料金のページ](https://developers.cloudflare.com/durable-objects/platform/pricing/)で確認):

- リクエスト: 1日10万回。リスナーがビンゴのページに戻るたびに1回かかる。画面のファイルの配信は数えない。
- データの読み書き: 1日あたり読み取り500万行、書き込み10万行。
- 超えるとエラーになり、日本時間の午前9時に戻る。

目安として、500人が1回の配信で75回ずつページに戻っても約3.8万回で、上限に収まります。
先に効いてくるのは書き込みのほうです。上限いっぱい(500人・5,000枚)で1日に3ゲーム遊ぶと、
書き込みは上限の5〜7割になる見積もりです(手元での計測からの概算)。100人・数百枚の規模なら、数%で済みます。
これを超える規模になったら、有料プラン(月5ドル)に切り替えてください。1日の上限がなくなります。

## ファイル構成

```
bingo/
  wrangler.jsonc     Cloudflareの設定(Workerの名前、画面のファイルの場所、保存先)
  package.json       開発用の道具(wrangler)とテストのコマンド
  src/
    index.mjs        入口。/ws を部屋へ渡す
    room.mjs         部屋(Durable Object)。接続・権限・抽選・判定
    store.mjs        保存(SQLite)の読み書き
  public/
    index.html       リスナー画面
    player.mjs       リスナー画面の動き
    host.html        主催者画面
    host.mjs         主催者画面の動き
    logic.mjs        カードの生成と列の判定(サーバーと画面で共用)
    net.mjs          切れても自動でつなぎ直す接続
    view.mjs         カードや確認ダイアログなどの部品
    style.css        見た目
    _headers         セキュリティのためのHTTPヘッダー
  test/
    logic.test.mjs   カードの生成と判定のテスト
    room.test.mjs    サーバーのテスト
    e2e.test.mjs     画面のテスト(Playwright)
    helpers.mjs      テスト用の共通部品
```

抽選・カードの生成・ビンゴの判定は、すべてサーバー側で行います。リスナーの画面を書き換えても、結果は変わりません。
個人情報は自己申告の名前だけで、Cookieや追跡は使いません。

## 手元で動かす

Node.js 22以上が必要です。

```bash
cd bingo
npm install
echo 'HOST_PASSWORD=てすと用の合言葉' > .dev.vars
npm run dev
```

`http://localhost:8787/` がリスナー画面、`http://localhost:8787/host` が主催者画面です。`.dev.vars` はリポジトリに入りません。

## テスト

```bash
cd bingo
npm test          # カードの判定とサーバー
npm run test:e2e  # 画面(Playwright と Chromium が必要)
```

どちらも、手元で `wrangler dev` を自動で起動して確かめます。Cloudflareのアカウントは要りません。
画面のテストは Playwright を使います。入っていなければ、次で入れてください(`package.json` には含めていません)。

```bash
npm install --no-save playwright
npx playwright install chromium
```

## 注意(このリポジトリの同期について)

`publish_public.sh` は、Dropbox側の元フォルダから `rsync --delete` でこのリポジトリへ同期します。
GitHub側にだけ `bingo/` と `docs/` があると、次の同期で削除されます。
Cloudflareは `main` の内容をそのまま公開するので、`bingo/` が消えると次の自動公開が失敗します
(すでに公開されているものは、そのまま動き続けます)。
元フォルダにも `bingo/` と `docs/` をコピーしておいてください。`bingo/node_modules/` と `bingo/.wrangler/` はコピー不要です。
