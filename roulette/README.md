# みんなでルーレット(カジノ式・リスナー参加型)

配信者がディーラー、リスナーがお客さんになって遊ぶ、カジノ式のルーレット。
リスナーは自分のスマホでチップを賭け、配信者が「回す」を押すと、全員の画面で同じ盤が回って同じ数字に玉が落ちます。

- 配信者用URL: `https://gyouzaurusu.github.io/stock-analyzer/roulette/`
- リスナー用URL: 部屋を作ると画面に出ます(`…/roulette/?room=部屋コード`。QRコードも出ます)

登録もアプリのインストールも要りません。追加の設定も要りません(チンチロと同じ Firebase をそのまま使います)。

> チップは遊び用の点数です。お金や景品とは交換できません。

> URL の先頭(`gyouzaurusu`)は GitHub のアカウント名です。アカウント名を変えるまでは、`gyouzaurusu` のところが前の名前になります。

## ルール

本物のカジノと同じ「ヨーロピアン式」(0 が 1 つ、0〜36 の 37 マス)。

| 賭ける場所 | 当たると | 当たる数字 |
|---|---|---|
| 数字ぴったり(0〜36) | 36倍 | その数字だけ |
| 1〜12 / 13〜24 / 25〜36 | 3倍 | その 12 個 |
| たて1列 | 3倍 | テーブルのその列の 12 個 |
| 赤 / 黒 | 2倍 | その色の 18 個 |
| 奇数 / 偶数 | 2倍 | その 18 個 |
| 1〜18 / 19〜36 | 2倍 | その 18 個 |

- 「36倍」は、賭けたチップを含めて 36倍もどる、という意味(10 賭けて当たると 360 もどり、350 の増え)。
- **0 が出たら、0 に賭けた人だけが当たり**(赤黒・奇数偶数などは全部はずれ)。この 0 のぶんだけ、ディーラー(配信者)が少し有利。
- 最初は全員 1,000 チップ。賭けは 10 チップから。何か所に賭けてもよい。
- チップがなくなったら「おかわり」で 1,000 にもどせる(回数が順位表に出る)。

## 使い方

### 配信者(ディーラー)

1. 配信者用URLを開き、「ルーレットを始める(部屋を作る)」を押す。
2. **部屋コード(4文字)**・リスナー用URL・QRコードが出るので、配信に映す。「URLをコピー」でURLをコピーできる。
3. リスナーが賭けると、テーブルにチップの合計が出る。そろったら「💗 ベット締め切り → 回す」。
4. 玉が転がって止まると、出た数字・当たった人・増えたチップが出る。順位表が入れ替わる。
5. 「次のゲームへ」で、テーブルを片づけて賭けの受付を始める。
6. やめるときは「部屋を閉じる」。再読み込みしても同じ部屋に戻る。

- 「チップの順位」には全員のチップと、「配信者(ディーラー)の収支」(はずれて集まった分 − 当たって払った分)が出る。
- 「チップを配り直す」で、全員を 1,000 チップに戻せる(おかわりの回数と収支も 0 に戻る)。
- 荒らし対策: 順位表の各行の「非表示」(名前をどこでも「？？？」にする)と「ブロック」(この部屋に入れなくする。置いてある賭けも片づく)。

#### 配信に映す

- 配信者の画面をそのまま映す。
- または、配信ソフト(OBS など)の「ブラウザソース」で `…/roulette/?room=部屋コード&stage=1` を開く(ボタンのない表示専用。音は鳴らない)。

### リスナー(スマホ)

1. QRコードかURLを開く(配信者用URLを開いて、部屋コードを入れても入れる)。
2. 名前とアイコンを決めて「参加する」(「見るだけ」でも見られる。あとから参加もできる)。
3. 画面の下でチップ(10 / 50 / 100 / 500)をえらび、テーブルの場所をタップして置く。同じ場所を何度も押すと重なる。
   ピンクの丸が自分のチップ、白い丸がほかの人の合計。「取り消す」で置いたチップが全部もどる。
4. 配信者が回すと「ノーモアベット!」。玉が止まると、当たり・はずれと増減が出る。

### 音が出ないとき

- 画面の下に「🔇 タップで音をオン」が出ていたら、画面のどこかをタップする(ブラウザは一度触るまで音を出さない)。
- 🔊 ボタンでミュートになっていないか確かめる。
- iPhone の消音スイッチ(マナーモード)が入っていても、配信者の画面は鳴る(その間、聴いていた音楽は止まる)。リスナーは消音スイッチを切ると鳴る。

## 公平さについて

- 出る数字は、配信者の画面が「回す」の瞬間に端末の乱数(暗号用の乱数)で 0〜36 から同じ確率で決める。回り始める前に決まっていて、演出で結果は変わらない。
- チップの計算は配信者の画面だけが行う。リスナーの画面からは、自分のチップを書きかえられない。
- 途中から開いた人には、出ている結果がそのまま見える(回る演出は再生しない)。

## しくみ(作る人向け)

- 公開は GitHub Pages。`roulette/` フォルダが `main` にあれば、そのまま上のURLで公開される。ビルドは無い。
- 端末どうしの同期は Firebase Realtime Database。**チンチロ(`chinchiro/`)と同じ Firebase プロジェクト・同じセキュリティルール**を使う。
  だから Firebase 側の追加の作業は無い(`firebase-config.js` はチンチロと同じ内容。公開してよい値)。
  - ルールは `chinchiro/firebase-rules.json`(`rooms/$code` 以下)。部屋は `rooms/RL-コード` に置き、チンチロの部屋(4文字そのまま)とは重ならない。
  - 配信者だけが書けるもの: `state`(何回戦か・全員のチップ・テーブルの賭け・出た数字・出目の記録・収支)。
  - リスナーが書けるもの: 自分の名前(12文字まで)・アイコン・合図(`actions`)・接続中の印だけ。
  - **賭けの送り方**: いまのルールでは、リスナーが `actions` に書けるのは `{ type: 'roll', at: 数 }` だけ。
    そこで「何回戦・どこに・いくら」を 1 つの数(`at`)に詰めて送る(`logic.js` の `encodeOp` / `decodeOp`)。
    配信者の画面がそれを確かめて(回戦が合っているか・受付中か・チップが足りるか)、`state` に反映し、合図を片づける。
    一度に送れる合図は 1 人 1 つなので、リスナーの画面は順番に 1 つずつ送る(同じ場所への連打はまとめる)。
  - アイコンは、ルールが許す12個の名前(`char`)を絵文字の番号として使っている(`app.js` の `ICONS`)。
  - ルールを変えるときは、チンチロと両方が動くことを確かめる。
- 無料枠(同時100接続)はチンチロと共用。部屋を見ている人が80人を超えると、新しく開いた人は「満員」になる。
- 回転は、出る数字と動きの種を先に決めて 1 回だけ書き込み、各端末が同じ計算で同じ動きを描く(`logic.js` の `planSpin` / `pose`)。
  精算(チップの増減)も同じ書き込みで済ませるが、玉が止まるまで、結果・チップ・出目の記録は画面に出さない。
- アカウント名を変えたあと「このサイトが Firebase に許可されていません」と出たら、Firebase の Authentication →「設定」→「承認済みドメイン」に、画面に出たドメインを足す。

### ファイル構成

```
roulette/
  index.html          画面の骨組み(役割で切り替え)
  style.css           見た目(ピンク基調。ほかのアプリとは別のデザイン)
  logic.js            盤の並び・賭ける場所と倍率・合図の詰め方・精算・玉の動き・進行(純粋関数)
  sync.js             同期アダプタ(mock / firebase)
  wheel.js            盤とテーブルの絵・玉が転がる演出・音
  app.js              配信者・リスナー・表示専用の画面
  firebase-config.js  Firebase の設定(チンチロと同じ)
  test/               node --test(ロジック・絵・同期)と Playwright(画面)
```

### 試す・テスト

`…/roulette/?mock=1` を付けると、Firebase なしで同じブラウザ内(別タブ)だけで同期して試せる(お試し専用。他の端末とはつながらない)。
お試しのときだけ、配信者のURLに `&n=17` を付けると出る数字を決め打ちできる(本番では効かない)。

```bash
node --test roulette/test/logic.test.mjs roulette/test/wheel.test.mjs roulette/test/sync.test.mjs
node --test roulette/test/e2e.test.mjs   # Playwright + Chromium が必要(mock 同期で動く)
```

JS/CSS を変えたら、公開する前に次を実行する(`index.html` の読み込みに付けた印 `?v=…` を中身に合わせて更新する。合っていないと画面のテストが失敗する)。

```bash
node roulette/test/stamp-version.mjs
```

## 注意(このリポジトリの同期について)

このリポジトリには、Mac の Dropbox 側の元フォルダから同期する `publish_public.sh` があります。
以前の `publish_public.sh` は、元フォルダに無いものを消す(`rsync --delete`)ので、GitHub 側にしか無い `roulette/` は同期のときに消えていました。

いまの `publish_public.sh` は、配信アプリのフォルダ(`bingo/` `chinchiro/` `roulette/` `sugoroku/`)と `docs/` を同期の対象から外してあり、
同期しても消えず、古い内容で上書きされることもありません。

**ただし、同期で実際に動くのは Mac の Dropbox 側にある `publish_public.sh` です。**
Mac で同期を使う前に、Dropbox 側の `publish_public.sh` を、このリポジトリの新しいものに置き換えてください(一度だけ)。
置き換える前に古いもので同期すると `roulette/` が消えます。消えてしまったときは、消える前の状態に戻せば元どおりになります。

新しい配信アプリのフォルダを足したときは、`publish_public.sh` の「同期しないフォルダ」にもそのフォルダを足してください。
