# みんなでルーレット(リスナー参加型)

配信者とリスナーが、それぞれの端末からつながって遊ぶルーレット。
配信者が「回す」を押すと、全員の画面で同じルーレットが同時に回り、同じ結果で止まります。

- 配信者用URL: `https://suesugi60.github.io/stock-analyzer/roulette/`
- リスナー用URL: 部屋を作ると画面に出ます(`…/roulette/?room=部屋コード`。QRコードも出ます)

登録もアプリのインストールも要りません。追加の設定も要りません(チンチロと同じ Firebase をそのまま使います)。

> 飲みのお題を入れるときは、飲めない人はソフトドリンクでOK。無理な飲酒は絶対にしないこと。

## 遊び方は2つ

| | 何が回る? | 使いどころ |
|---|---|---|
| 🎀 お題ルーレット | 配信者が入れた項目(罰ゲーム、当たりはずれ、数字 など) | お題決め、罰ゲーム、プレゼントの中身決め |
| 🙋 リスナー抽選 | 「参加する」を押したリスナーの名前 | プレゼントの当選者決め、次に話す人決め |

画面の上のボタンで、いつでも切り替えられます。

## 使い方

### 配信者

1. 配信者用URLを開き、「ルーレットを始める(部屋を作る)」を押す。
2. **部屋コード(4文字)**・リスナー用URL・QRコードが出るので、配信に映す。「URLをコピー」でURLをコピーできる。
3. 「💗 回す」を押すと、みんなの画面でルーレットが回る。止まると結果が大きく出て、紙吹雪が舞う。
4. 結果は「結果の記録」に新しい順で30件まで残る。「結果を閉じる」で結果の表示を消せる(次に回しても消える)。
5. やめるときは「部屋を閉じる」。再読み込みしても同じ部屋に戻る。

#### お題ルーレットの中身を変える(「ルーレットの中身」)

- 文字を書きかえる、「＋ 項目を足す」で足す、「✕」で消す。30項目・1項目20文字まで。変えるとすぐ全員の盤に出る。
- 右の数字は**当たりやすさ**(1〜9)。大きいほど幅が広くなって当たりやすい。
- 「見本から入れる」で、当たりはずれ / 罰ゲーム / 飲み / 数字 1〜6 / はい・いいえ の見本と入れ替えられる。
- 「当たった項目は消していく」をオンにすると、当たった項目が次から盤に出なくなる(全部ちがう結果にしたいとき)。

#### リスナー抽選

- リスナーが「参加する」を押すと「参加者」に並び、名前が盤に出る。対象が2人以上で回せる。
- 「抽選で当たった人は、次の抽選から外す」(最初はオン)。当たった人には「当選済み」の印が付く。
  「当選済みを元に戻す」で全員を対象に戻せる。
- 当たったあと「当たった人にお題を回してもらう」を押すと、お題ルーレットに切り替わり、その人のスマホに「回す!」が出る。

#### リスナーに回してもらう

「参加者」の「回してもらう」を押すと、その人のスマホが光って「💗 回す!」ボタンが出る。押すとみんなの盤が回る。
反応がないときは、配信者が「代わりに回す」か「指名を取り消す」。

#### 荒らし対策(「参加者」の各行)

- 「非表示」: 名前を盤・結果・記録のどこでも「？？？」にする。
- 「外す」: 参加者から外す(本人はもう一度参加できる)。
- 「ブロック」: この部屋に入れなくする。

#### 配信に映す

- 配信者の画面をそのまま映す。
- または、配信ソフト(OBS など)の「ブラウザソース」で `…/roulette/?room=部屋コード&stage=1` を開く(ボタンのない表示専用。音は鳴らない)。

### リスナー(スマホ)

1. QRコードかURLを開く(配信者用URLを開いて、部屋コードを入れても入れる)。
2. 名前とアイコンを決めて「参加する」(「見るだけ」でも見られる。あとから参加もできる)。
3. 抽選に当たると「🎉 当たり! あなたが選ばれました!」と出る。回す役に選ばれると「💗 回す!」が出る。

### 音が出ないとき

- 画面の下に「🔇 タップで音をオン」が出ていたら、画面のどこかをタップする(ブラウザは一度触るまで音を出さない)。
- 🔊 ボタンでミュートになっていないか確かめる。
- iPhone の消音スイッチ(マナーモード)が入っていても、配信者の画面と、回す番のリスナーのスマホは鳴る(その間、聴いていた音楽は止まる)。
  見ているだけの人は、消音スイッチを切ると鳴る。

## 公平さについて

- 結果は、配信者の画面が「回す」の瞬間に端末の乱数(暗号用の乱数)で決める。回り始める前に決まっていて、演出で結果は変わらない。
- 当たる確率は、当たりやすさの数字(=盤の幅)に比例する。全部 1 なら全部同じ確率。
- 途中から開いた人には、出ている結果がそのまま見える(回る演出は再生しない)。

## しくみ(作る人向け)

- 公開は GitHub Pages。`roulette/` フォルダが `main` にあれば、そのまま上のURLで公開される。ビルドは無い。
- 端末どうしの同期は Firebase Realtime Database。**チンチロ(`chinchiro/`)と同じ Firebase プロジェクト・同じセキュリティルール**を使う。
  だから Firebase 側の追加の作業は無い(`firebase-config.js` はチンチロと同じ内容。公開してよい値)。
  - ルールは `chinchiro/firebase-rules.json`(`rooms/$code` 以下)。部屋は `rooms/RL-コード` に置き、チンチロの部屋(4文字そのまま)とは重ならない。
  - 配信者だけが書けるもの: `state`(盤の中身・回転・結果・記録・指名・当選済み)。
  - リスナーが書けるもの: 自分の名前(12文字まで)・アイコン・参加(`queue`)・「回す」要求(`actions`)・接続中の印だけ。
  - アイコンは、ルールが許す12個の名前(`char`)を絵文字の番号として使っている(`app.js` の `ICONS`)。
  - ルールを変えるときは、チンチロと両方が動くことを確かめる。
- 無料枠(同時100接続)はチンチロと共用。部屋を見ている人が80人を超えると、新しく開いた人は「満員」になる。
- 回転は「どこに止まるか」を先に決めて1回だけ書き込み、各端末が同じ計算で同じ動きを描く(`logic.js` の `planSpin` / `angleAt`)。
  盤が止まるまで、結果・記録・消える項目は画面に出さない。

### ファイル構成

```
roulette/
  index.html          画面の骨組み(役割で切り替え)
  style.css           見た目(ピンク基調。ほかのアプリとは別のデザイン)
  logic.js            項目・抽選・角度・進行(純粋関数)
  sync.js             同期アダプタ(mock / firebase)
  wheel.js            盤の絵(SVG)・回る演出・音
  app.js              配信者・リスナー・表示専用の画面
  firebase-config.js  Firebase の設定(チンチロと同じ)
  test/               node --test(ロジック・絵・同期)と Playwright(画面)
```

### 試す・テスト

`…/roulette/?mock=1` を付けると、Firebase なしで同じブラウザ内(別タブ)だけで同期して試せる(お試し専用。他の端末とはつながらない)。

```bash
node --test roulette/test/logic.test.mjs roulette/test/wheel.test.mjs roulette/test/sync.test.mjs
node --test roulette/test/e2e.test.mjs   # Playwright + Chromium が必要(mock 同期で動く)
```

JS/CSS を変えたら、公開する前に次を実行する(`index.html` の読み込みに付けた印 `?v=…` を中身に合わせて更新する。合っていないと画面のテストが失敗する)。

```bash
node roulette/test/stamp-version.mjs
```

## 注意(このリポジトリの同期について)

このリポジトリには、Mac の Dropbox 側の元フォルダから同期する `publish_public.sh` があります。
以前の `publish_public.sh` は、元フォルダに無いものを消す(`rsync --delete`)ので、GitHub 側にしか無い `roulette/` は同期のときに消えていました。

いまの `publish_public.sh` は、配信アプリのフォルダ(`bingo/` `chinchiro/` `roulette/` `sugoroku/`)と `docs/` を同期の対象から外してあり、
同期しても消えず、古い内容で上書きされることもありません。

**ただし、同期で実際に動くのは Mac の Dropbox 側にある `publish_public.sh` です。**
Mac で同期を使う前に、Dropbox 側の `publish_public.sh` を、このリポジトリの新しいものに置き換えてください(一度だけ)。
置き換える前に古いもので同期すると `roulette/` が消えます。消えてしまったときは、消える前の状態に戻せば元どおりになります。

新しい配信アプリのフォルダを足したときは、`publish_public.sh` の「同期しないフォルダ」にもそのフォルダを足してください。
